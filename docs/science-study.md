- 첫 화면 → 과학 → 생물 / 지구과학 / 물리학Ⅱ

## 관측 실습

- **파인더 정렬:** 주망원경 중앙의 별과 파인더 십자선을 일치시키는 조작. 오차는 화면의 모형 단위이며 실제 각도나 나사 회전량이 아니다.
- **극축 정렬 원리:** 관측지 위도와 축 고도를 비교하고 방위 오차를 함께 조절한다. 작은 각도에서 `hypot(고도차, 방위차×cos 위도)`로 축 오차를 근사한다. EM-200 극축망원경의 실제 눈금·날짜 설정은 수업자료의 절차를 따른다.
- **천구 좌표·계획:** 위도·적위·시간각에서 지평 좌표를 구한다. `H=(LST−RA)×15°`, 방위각은 북쪽 0°에서 동쪽으로 증가한다. 천정·천저에서 방위각은 정의하지 않는다. 굴절·지형·날씨·광해는 포함하지 않는다.
- 모의 연습 기록은 기기에 저장하고 CSV로 내려받는다. 실제 관측 수행평가의 관측값과 구분한다.

## 문항 검증과 공동 작업

기존 Supabase 926개 카드와 작업 시작 시 최신 main의 `db/cards.json`을 필드별로 비교해 일치를 확인했다. 기존 카드 내용의 변경·삭제는 없다. 모든 카드의 보기 중복·출처·영어 지문·범위 연결은 저장소 테스트로 확인한다. 신규 물리 문항은 조건·단위·정답·교재 쪽수와 개념의 연결을 검토했다. 전체 기존 문항의 사실관계를 새 원자료와 전부 대조한 검수로 해석하면 안 된다. 특정 문항의 문맥 오류가 확인되면 카드 ID와 원자료를 함께 확인해 DB와 번들에 같은 수정으로 반영한다.

### DB 반영 상태와 마지막 단계

**이 브랜치에서는 DB 쓰기를 실행하지 않았다.** 사용자가 Supabase 플러그인 설치를 거절했으며 공개 키에는 읽기 권한만 있다. DB 우선 동작은 그대로 유지한다.

1. 프로젝트 팀 멤버가 Supabase **SQL Editor**에서 `db/physics-release.sql`을 검토한 뒤 실행한다.
2. 기존 카드 926개는 그대로 두고 `physics-ii` 덱·객관식 72개·서술형 18개를 추가한다. 메뉴 재분류에 따른 덱 표시 정보도 최신으로 맞춘다.
3. ID가 이미 있으면서 내용이 다르거나 기존 덱 정보가 공동작업 중 변경됐으면 **전체 트랜잭션이 중단**된다. 강제로 덮어쓰지 말고 변경 사항을 먼저 비교한다. 같은 내용으로 재실행은 가능하다.
4. 마지막 조회 결과가 choice=72, written=18인지 확인하고 PR에 DB 반영 완료를 기록한다.
5. CI 통과와 DB 일치를 확인한 뒤 PR을 합친다. main 병합 후 GitHub Pages가 배포된다.

`seed.sql` 전체 실행 대신 이번 변경만 담은 `physics-release.sql`을 사용한다. 비밀 키·비밀번호를 공유할 필요가 없다. 온라인 공동작업은 Supabase 팀 멤버가 DB에서 수행하며, 사이트의 풀이·관측 연습 기록은 개인 기기에 저장된다.
